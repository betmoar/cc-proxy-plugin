# Changelog

All notable changes to cc-proxy are recorded here. Versions follow [semver](https://semver.org/); `package.json` is the single source of truth and propagates to `.claude-plugin/plugin.json` via `scripts/sync-version.mjs`.

## [0.8.0] — 2026-08-30

### Added
- **LM Studio is a routable backend** (`LMSTUDIO_BASE_URL`). Self-hosted, selector-only: `lmstudio:<model-id>` reaches a model on your own LM Studio server, whose Anthropic-compatible skin at `/v1/messages` is the only documented endpoint — baseUrl passthrough needs no rewriting. Gated on the base URL rather than a key (the host is per-user infrastructure and server auth is often off); `LMSTUDIO_API_KEY` optional (Bearer; the server also accepts `x-api-key`; LM Studio's own docs use the dummy token `lmstudio`). `match()` refuses every id — local model names are arbitrary and churn with each load/unload, and a live server held bare `glm-*`, bare `qwen*` and slash ids side by side, so any shape predicate would steal routes from GLM/Qwen/OpenRouter. `lmstudio:<id>` (or `DEFAULT_BACKEND=lmstudio`, the documented explicit fallback) is the only way in. Billing `local` (tier 0) added for the PROVIDER_BILLING coherence lock. Probed live 2026-08-28: Messages 200, **tool_use works** (undocumented by LM Studio but the make-or-break fact for CC sessions), SSE framing standard, inbound thinking blocks tolerated. Two `probe:vendors` cases added, keyed on `LMSTUDIO_BASE_URL` and deriving the URL from it. No discovery leg: a per-machine catalog has no place in the curated `/v1/models` publishing contract.
- **Request-id correlation (issue #46).** One opaque id per request, echoed as `x-request-id` (an inbound id is honored — charset-allowlisted and capped at 64 — otherwise one is minted) and stamped on the routing-log line, so with one shared proxy across sessions "which of these interleaved lines was mine" has an answer. The buffered path also harvests the vendor's own `request_id` from error bodies onto `[vendor-request-id]` lines — correlating an OpenRouter `gen-…` rejection with the routing decision no longer means reading raw bodies. Both id inputs are sanitized to `[A-Za-z0-9._-]`: the id interpolates into a log line `parseRoutingLines()` filters on `starts-with-[` + `contains-" -> "`, and unsanitized values of either kind were demonstrated (during review) to forge plausible routing history in `/cc-proxy:status` output. `scripts/status.js` keeps whole lines, so the `{id}` segment reaches the report; older id-less log lines still parse.
- **Two LM Studio cases in `pnpm probe:vendors`** — the Messages skin (200 + `stop_reason`) and tool_use over the skin (200 + `tool_use`; run at `max_tokens: 300` because at 64 the model sometimes spends the budget reasoning and returns an empty 200). Keyed on `LMSTUDIO_BASE_URL` — skipped when no host is configured — with the URL derived from that var (a literal would probe a machine the operator does not have) and the token mirroring the provider (`LMSTUDIO_API_KEY` or the `lmstudio` dummy).

### Fixed
- **A malformed `LMSTUDIO_BASE_URL` killed the whole proxy on the first request.** Every other backend's base URL is a hardcoded literal; this one is free-form user input, and LM Studio's own UI shows its address WITHOUT a scheme (`192.168.1.50:1234`) — exactly what a user pastes. That value reached `new URL(baseUrl + req.url)` inside the request dispatcher, which has no `try`, so the throw ended the process: measured exit code 1, no response written, and every concurrent Claude Code session dropped, not just the misconfigured one. Two defences now: `buildProviders()` validates the URL and refuses to register the backend (loud stderr line, other backends unaffected), and `upstreamRequestOptions()` converts an unusable base URL into a typed `UpstreamConfigError` that both forward paths answer as a `502` — the second one matters for any future provider whose baseUrl comes from config.
- **`body.model` could forge routing history in `/cc-proxy:status`.** The correlation-id work sanitized the inbound header and the vendor's `request_id`, but `model` — attacker-controlled JSON that predates both — was interpolated into the same log line unescaped. A newline plus a fake `[<iso>] {id} X -> Y /path` produced a second line that `parseRoutingLines()` kept as genuine routing history (reproduced end-to-end). All four log sites now escape line-structural characters via `logSafe()`; the id stays readable because a model id is a value the operator needs to read, not an opaque token. The lesson is the sweep, not the patch: two of three sites in one defect class were hardened, and the third stayed open because nobody looked for it.
- **An upstream `x-request-id` silently replaced the proxy's own.** `writeHead(status, headers)` REPLACES what `setHeader()` put on the response, so any backend emitting its own correlation header (OpenAI-shaped servers commonly do) took over the id — measured on both the buffered and streaming paths: the log line said `{proxy-owned-id}` while the client received the vendor's. The correlation feature quietly stopped working for exactly the backends most likely to emit tracing headers. Upstream `x-request-id` is now dropped from the forwarded header set at every site.

- **Three comment corrections, two of them factually wrong claims.** The `vendorRequestIdOf` JSDoc cited Anthropic's error shape as a nested `request.id`; Anthropic actually puts `request_id` at the TOP LEVEL beside `error`, which the lookup chain already covered via a different branch — and the speculative `b?.request?.id` fallback the mis-citation described, which no vendor is known to emit and no test exercised, is deleted rather than left as an unfalsifiable guard. The probe comment claimed LM Studio's docs don't document tool use on the Anthropic skin; they do (a `get_weather` cURL with `input_schema` on the compat page) — what they omit is a sample RESPONSE with a `tool_use` block, which is the narrower thing the probe actually establishes. And `requestIdOf`'s collision note said "negligible" without computing it: at a full 5 MB log window (~69k lines at ~76 bytes) the birthday bound gives ~42% odds that some pair of lines shares a tag. That remains acceptable — a collision merges two log tags and never misroutes a request — but the comment now states the real number and the reason, and `2^-52` is corrected to `2^-53` (`Math.random`'s actual grid).
- **`tierOf("lmstudio") -> 0` is now a `@doctest`.** Every sibling tier claim in that JSDoc is executed; the newest one was prose. The file already learned this lesson once.

- **Two coverage gaps closed, both mutation-verified.** The media-generation tunnel gained `reqId` plumbing in this release and had no test touching it — deleting that plumbing left the whole suite green, which is the exact case CLAUDE.md's "if you change forwarding and no test fails, you haven't tested it" rules out. It now asserts the `x-request-id` echo, that the log tag matches the header the client received, and that a vendor `request_id` on a tunnel error is harvested under the same id. Separately, `DEFAULT_BACKEND=lmstudio` was pinned at the `resolve()` level only: the routing decision was locked, the forward never exercised. It now proves bytes arrive at the LM Studio stub on both the buffered and streaming paths with the right bearer credential and no inbound-credential leak, that nothing falls through to the previous default, and — the consequential one — that invariant 4 still outranks the fallback, so Claude Code's internal haiku ops never reach a local box.

- **Three more coverage gaps closed, all mutation-verified — same lesson as the sweep above.** The two-defence story for a malformed base URL was pinned on the BUFFERED path only: deleting `forward()`'s entire `try` around `upstreamRequestOptions()` — restoring the exact process-killing throw — left the whole suite green, because the test posted without `stream: true` and only ever reached `forwardBuffered()`'s copy of the guard. It is now parametrized over both paths and additionally asserts the proxy still serves a DIFFERENT backend afterwards, which is the actual claim ("one bad request, not a dead proxy"). Likewise the upstream-`x-request-id` strip was pinned on the two normal-size 200 sites, leaving both SIZE-CAP ESCAPE HATCHES — the >64 KiB 429 passthrough in `forward()` and the >1 MiB passthrough in `forwardBuffered()` — revertible to a bare `upstreamRes.headers` with 464/464 still passing. Each has its own `writeHead`, so each was its own chance to leak the vendor's id; both now assert it. Every `writeHead` that forwards upstream headers is a separate defect site, and "the fix is applied at all five" is not the same claim as "all five are tested".
- **Two comment corrections.** `isValidHttpUrl`'s JSDoc said a `file:`/`data:` URL "picks neither of the two agents" — `pickAgent()` is `proto === https ? httpsAgent : httpAgent`, a binary choice with no third outcome, and `upstreamRequestOptions()` resolves any non-https protocol to the plain `http` module, so such a URL gets `httpAgent` with an empty hostname and fails asynchronously on the socket. The comment now describes what actually happens and why the scheme check still earns its keep (these values parse, so they slip past the `try` and are caught nowhere else). And invariant 1 in `CLAUDE.md` still said "one header exception" after this release added a second.
- **Prompt caching documented and its precondition locked.** Both README and ARCHITECTURE have claimed since 0.1 that "prompt-cache works unchanged" through the proxy — never verified, and non-obvious, since the thinking-strip rewrites the very prefix bytes a cache keys on. Measured 2026-08-29 against Z.ai through the running proxy: a cold turn billed `input_tokens=2816, cache_read=0`; the identical prefix billed `64` with **2752 read from cache**; and the worst case — a `thinking` block deep *inside* the cacheable prefix — still read **4416** on repeat. The claim holds for a specific reason nothing recorded: `stripAssistantThinking()` is DETERMINISTIC, so the backend receives byte-identical bytes every turn and the cache key is stable. Make that strip depend on anything request-varying and every turn becomes a full-price miss with no error and no failing test; `test/sanitize.test.js` now pins both determinism and `cache_control` survival (mutation-verified: a counter in the strip fails one, dropping breakpoints fails the other). `docs/OPERATIONS.md` gains a per-backend matrix (activation, write/read multipliers, TTLs) sourced from OpenRouter's prompt-caching guide, plus the three consequences that bite: Anthropic's model-dependent minimum cacheable prefix (1,024 vs **4,096** on Opus 4.5–4.8 and Haiku 4.5), its four-breakpoint limit, and the fact that a mid-session `/model` hop discards the warm cache entirely — the largest avoidable token cost in normal use.

### Changed
- **Gateway model discovery measured and documented as an opt-in (issue #44).** Claude Code ≥2.1.129 can populate its `/model` picker from a gateway's `/v1/models` when `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` — and cc-proxy's publishing contract already satisfies it. But the measurement (gate logic decoded from the CC 2.1.250 bundle, then live-verified) reversed the premise: CC requires a credential (`ANTHROPIC_AUTH_TOKEN`, which demotes the claude.ai OAuth login) and keeps **only ids matching `/claude|anthropic/i`** — zero matches aborts discovery — so third-party ids never reach the picker and the one-custom-slot workflow stands. Documented in README + OPERATIONS with the tradeoffs; cc-proxy itself needed zero code changes.
- **Registry-order note**: LM Studio sits before `claude` and after `qwen`; the `PROVIDER_IDS` coupling test and the couplings table were updated with the new env vars and the log-template change in the same commits that touched their counterparts.

## [0.7.0] — 2026-08-25

### Added
- **`GET /v1/models?dedup=identity` — one entry per MODEL, not per id (issue #39).** An id names the ROUTE as well as the model, so the same weights appear several times: `deepseek-v4-pro` (native, tier 3), `qwen:deepseek-v4-pro` (plan, tier 2) and `deepseek/deepseek-v4-pro` (reseller, tier 4) are one model on three routes. The natural way to pick a diverse set — one model per `provider`, best `grade` — therefore picks the same model twice, and no duplicate check catches it because the id strings genuinely differ. It reads as independent agreement, which for a consumer seating models against each other is the one thing that must never be manufactured. The parameter collapses each group to its **lowest tier** (same weights, cheaper route), with a `usable` entry always beating an unusable one whatever its tier. Opt-in: with no parameter the response is unchanged, and an unrecognized value is a `400` rather than a quietly un-deduped list — a consumer that typos `?dedup=identiy` would otherwise get a wrong answer that looks right.
  **Split on the FIRST separator, and that is the whole subtlety.** `/` and `:` are not interchangeable route markers: `/` is OpenRouter's vendor namespace while a TRAILING colon is an OpenRouter structural variant (`:batch`, `:free`). Measured over a live 415-id catalogue: 66 ids carry both, and last-separator splitting merges 50 of them into one identity called `batch` spanning seven vendors. The issue's own first draft proposed exactly that rule — which is the argument for applying it once here instead of asking every consumer to re-derive it. 17 groups out of 396 identities are affected.
  **Publishes no new field.** An `origin:` field was the first design and was rejected: a published attribution is a fact that can go stale, whereas `provider` and `tier` are things the proxy observes, and `identityOf` reads the id itself. It also would not have caught `qwen/qwen3.7-max` vs `qwen3.7-max`, where both would say `origin: qwen`.
- **The Qwen plan's image models are reachable again, through a passthrough tunnel (issue #40).** `wan2.7-image` and `wan2.7-image-pro` are **included in the Token Plan** and were listed `usable: false`, so a plan holder reached for a paid alternative (`google/gemini-3.1-flash-image` at $0.068/image, and without an alpha channel). They were never broken — they want DashScope's own request schema, on a path cc-proxy did not route to. `POST /api/v1/services/aigc/multimodal-generation/generation` now forwards to the plan host: byte-for-byte body, the vendor's own response, no schema knowledge in the proxy. **A tunnel, not a translation**, so invariant 5 stands — all cc-proxy adds is the credential it already holds, which is what a caller with its own image client actually wants. `x-dashscope-sse: enable` selects the streaming path (DashScope streams via a request header, not a body field). Verified live 2026-08-25: 200, and the body carries a **signed OSS URL with an `Expires`** rather than inline base64, so a caller must fetch before it passes.
  **The one path-routed request in the proxy, necessarily.** Everything else routes on `body.model`, and `wan2.7-image` matches no provider predicate — no slash, no `qwen` prefix, not dated, not a plan resell — so without this branch it falls through to the DEFAULT backend and goes to Anthropic on the user's OAuth credentials. With no `DASHSCOPE_API_KEY` the path answers `503` for the same reason: falling through would be invariant 3 broken in the least visible way available.
  A second base URL (`mediaBaseUrl`) rather than a path rewrite: `upstreamRequestOptions()` concatenates `baseUrl + req.url` unconditionally, so routing this through the Anthropic skin's baseUrl yields `/apps/anthropic/api/v1/…` and 404s. There is no path-rewriting layer and this deliberately does not add one.
  **The audio ids stay `usable: false`, and that is now measured rather than assumed.** For `qwen-audio-3.0-tts-plus`, every HTTP candidate 400s with `InvalidParameter: url error` (`/text2speech/speech-synthesis`, `/speech-generation/generation`, `/services/audio/tts`, and multimodal-generation itself with a TTS body); `/compatible-mode/v1/audio/speech` 404s; `/compatible-mode/v1/chat/completions` with `modalities:["audio"]` 500s. The one route that ACCEPTS the task is WebSocket `/api-ws/v1/inference` — `task-started` arrives, so model and auth are valid — and then `task-failed`, `[cosyvoice:]Engine error [411]`, for every voice (Cherry / Ethan / longxiaochun), format (wav / mp3) and language tried. Vendor-side breakage, not a shape left to guess; and untunnellable here regardless, since the proxy has no `upgrade` handler.
- **`grade` on the six OpenRouter Gemini ids.** Every `google/*` id shipped without one, so a consumer dispatching by model strength could not reach any of them. `google/gemini-3.7-flash` is `Flagship`, `3.6-flash` `Strong`, and `3.5-flash` / `3.5-flash-lite` / `3.1-pro-preview` / `3.1-flash-lite` `Specialist`. **A flash model at Flagship is the house rule working, not failing:** grade is position within the vendor's OWN line, read from the vendor's numbering — the same rule that demoted `glm-5.2` under `glm-5.3`. benchlm corroborates rather than contradicts, with every Gemini Pro row sitting BELOW the flash line (`Gemini 3.6 Flash` rank 9 / 75.21 supported, `Gemini 3 Pro` rank 24 / 67.17, `Gemini 3.1 Pro` rank 96 / 55.96): Google's Pro tier is a price and context class, not the top of its capability line. `google/gemini-2.5-pro` is deliberately ungraded — a fossil, and 404 on Google's own API for new keys.
  **OpenRouter is the only leg Gemini has, and there will never be another.** Probed 2026-08-23 with a valid `GEMINI_API_KEY`: `/v1/messages`, `/v1beta/messages`, `/v1beta/anthropic/v1/messages` and `/anthropic/v1/messages` all 404 while `/v1beta/models/gemini-3.6-flash:generateContent` and `/v1beta/openai/chat/completions` returned 200 the same minute — not auth, not the free tier. Google publishes `generateContent` and an OpenAI skin, and invariant 5 bars the translation layer that would be needed for either. (A Gemini Plus subscription does not change this: Google's docs say plan benefits apply only within the AI Studio web interface.) Also worth recording from the #40 probes: Google's free tier does **not** include image generation — the error is a 429 that reads like exhaustion but says `limit: 0`, and retrying after the advertised `retryDelay` still yields 0.
  The half-fix this avoided: `vendorOf()` returned `undefined` for every `google/*` id, so `/cc-proxy:bench grades` would have written entries with no `grade` key and quietly stripped these curated grades off the wire on the next refresh — the two-copies drift `test/grades-refresh.test.js` exists to catch.
- **Two vendor cases in `pnpm probe:vendors`**, one positive and one negative, because both new claims are about someone else's server. The image case pins a 200 AND that the body still carries an image URL (a 200 with a different payload shape is a different fact). The TTS case pins the `Engine error [411]` failure — a "does not work" claim otherwise never gets re-examined, and if Alibaba fixes it the gate goes red instead of the comment rotting. The probe grew a WebSocket transport for it: the audio claim is unmeasurable over HTTP, and a fetch-only probe could record it only as "unreachable", which reads as "we could not check" rather than the fact it is.

### Fixed
- **A throw anywhere in the `/v1/models` handler killed the whole proxy.** `handleModels` is `async` and dispatched with neither `await` nor `.catch`, so any throw inside it became an unhandled rejection — which Node answers by terminating the process, taking every session on the machine with it and leaving the request itself unanswered. Measured on the pre-fix shape: exit code 1, no response written, and no `uncaughtException` handler anywhere in the repo to soften it. The whole body now sits in a `try` that logs the stack and answers `500`. The inner `try` around `collectModels()` stays and means something different — a failed *collection* degrades to a `200` with `_errors`, which is the endpoint's best-effort contract, whereas the outer one is pure containment. Locked by a test that poisons the payload and then asserts `/_status` still answers.
  The comment above the function had credited a `.catch` at the call site **that never existed** — protection described correctly and attributed to nothing, which is the worse half of comment rot: a reader who checks finds a plausible sentence and no code. Adding a second throw site (`dedupByIdentity`) outside the inner `try` is what made it matter.
- **`sendJson()` committed the response head before serializing the body**, so a payload that `JSON.stringify` refuses (a BigInt, a circular reference — both reachable from vendor-supplied data) left `headersSent` already true and no way to send a status. The client saw a socket hang up rather than an error. Serializing first makes the same failure recoverable: the caller's error path turns it into a real `500`. Mutation-verified in both directions.
- **The vendor probe's new WebSocket transport could crash the run and take the exit-code contract with it.** `JSON.parse` on an incoming frame was unguarded, so one non-JSON text frame from DashScope would kill `probe:vendors` with exit 1 — the code the script already spends on "a vendor disagrees with a source comment", making a crash indistinguishable from the one signal it exists to deliver, with every later case silently unreported. An unparseable frame is now `unreachable`. Two more: a clean close with no result is reported immediately instead of burning the full 30 s timeout and reporting a misleading "timed out", and `finish()` is now explicitly first-result-wins, since `ws.close()` fires `onclose` and would otherwise overwrite a real `task-failed` verdict with a fake network error. Verified against a fake vendor: non-JSON frame → reported, process survived; clean close → 160 ms; verdict-then-close → the verdict wins.

## [0.6.3] — 2026-08-14

### Added
- **`glm-5.3` is the new flagship GLM id, and `glm-5.2` demotes to `Strong`.** Z.ai shipped it 2026-08-14; `/cc-proxy:setup` now registers `glm-5.3[1m]` in the `/model` picker. It is **Z.ai-only** — probed the same day, the Qwen plan answers `Model not exist.` and OpenRouter does not list it — so its `ROUTES` entry has a single route and a plan-only user correctly falls through to their default backend rather than being routed somewhere that would 400.
  Two things worth knowing, both measured rather than assumed. **Z.ai currently serves `glm-5.3` for `glm-5.2`, `glm-5.1` and `glm-5` alike** — the response body comes back `"model":"glm-5.3"` for all of them. The grades are deliberately NOT derived from that: aliasing is a serving decision the vendor can reverse without notice, and the Qwen plan still serves real `glm-5.2` weights (it answers `"model":"glm-5.2"`), so collapsing those ids to one grade would publish a claim that is false for plan users and volatile for everyone else. `grade` stays what it has always been — position within the vendor's own line — which is why a new flagship demotes the previous one and nothing else moves.
  And **the vendor's own catalogs disagree with the vendor.** `/api/anthropic/v1/models` and `/api/paas/v4/models` both list 8 ids and neither mentions `glm-5.3`; only `/api/v1/models` knows it, and that endpoint lists just 2 ids. Anything that "auto-resolves the latest model" by reading the obvious endpoint would have confidently reported `glm-5.2` as current. The authoritative source is what the request path actually returns.
- **`pnpm probe:vendors` — the manual gate for claims about someone else's server.** `scripts/probe-vendors.mjs` re-issues the requests behind source comments that assert vendor behaviour ("Z.ai rejects a `[1m]`-suffixed model id") and exits non-zero when a vendor no longer answers the way the comment says. Deliberately **outside `pnpm check` and never in CI**: it needs real keys and spends real quota. It exists because this release shipped a design decision resting on an unverified vendor claim that later measured **false** — untestable offline is not the same as unfalsifiable, and a claim nobody can re-check is a claim nobody will.
- **Executable examples in source comments.** A comment of the form `@doctest fn(<json>) -> <json>` is parsed and run by `test/doc-examples.test.js`, so an input→output claim written next to an implementation fails the suite when it stops being true. Twelve examples cover `stripVariantSuffix` and `routingIdOf`, including every shape that actually rotted during this release. It is not an `eval`: one grammar, and calls dispatch through a whitelist, because comments are the least-reviewed text in the repo. Prose keeps carrying the *why* — only the mechanically-falsifiable half moves.

### Fixed
- **A `[1m]` variant suffix defeated three routing lookups at once (issue #34).** Claude Code spells a long-context variant `glm-5.2[1m]` — the form `ANTHROPIC_CUSTOM_MODEL_OPTION` registers and `/model` displays. Three lookups on the routing path are exact-match, and every one of them fails on a suffixed id: `ROUTES` (`Object.hasOwn`, so `rankRoutes` returns `[]`), `QWEN_PLAN_RESELLS` (`Set.has`), and `DATED_ID` (anchored `\d{4}$`, so `deepseek-v4-flash-0731[1m]` fails the test). The exposure is a **shared id whose only non-native route is the Qwen plan** — exactly the profile the `ROUTES` fallback exists to serve: with no GLM key, `glm-5.2[1m]` matched no route and no predicate and fell through to Claude, so a plan-only user's headline model changed backend with no error anywhere.
  **Latent, not user-facing.** CC strips the suffix before the wire today — 0 of 24070 routing lines in a real proxy log carry one — so this is a guard against that internal drifting (`[1m]` is not public API), which turns a future drift into a red test instead of a wrong backend.
  Stripped **once** in `resolve()` rather than at the three sites: a per-site patch fixes the two the issue named and leaves `DATED_ID` broken.
  **The stripped id also goes upstream, and that is a measurement.** Issue #34 asked whether the suffix survives to the vendor and said to verify before deciding; the first cut of this fix assumed it did and preserved it. Probed 2026-08-14 with real keys: `api.z.ai` returns `400 [1214][modelCode: does not exist]` for `glm-5.2[1m]` and `200` for `glm-5.2`; the Qwen plan gateway returns `400 InvalidParameter: Model not exist.` and `200` respectively. A wholly fake id (`glm-5.2-totally-fake`) draws the identical 1214, so the suffix is not a spelling any backend knows — forwarding it would route correctly and then fail at the vendor. It is Claude Code's own display spelling, so it is stripped on the way out exactly as the `<provider>:` lens is: a **third** deliberate exception to invariant 1, for the same reason as the second.
  A malformed bracket is never coerced into a routable id: the interior is `[^[\]]*`, not `.*`, which is the single shape where the two forms differ (`glm-5.2[a]b]` → left alone, where `.*` would synthesize `glm-5.2`). Mutation-verified: neutering the strip fails 5 tests, forwarding the raw suffix fails the end-to-end body assertion, loosening the interior fails the malformed-id guard, and dropping the `^` anchor fails the prefix guard.

### Changed
- **Documented that an inline `ANTHROPIC_BASE_URL=… claude` prefix is silently ignored (issue #25).** settings.json's `env` block overrides the process environment, so the natural way to point a session at a second proxy does nothing — and does it invisibly: the turn succeeds and the answer looks right while the request goes to whichever proxy settings.json names. Measured 2026-08-14 against two bare logging listeners, reading the *listener's* log rather than the client's stdout: the inline variant left :4400 with **zero** requests while the :4000 proxy gained 4 routing lines; `claude --settings '{"env":{…}}'` logged `POST /v1/messages?beta=true model=claude-opus-5` on :4401 with a 0 delta on :4000. The shell is not eating the variable (`node -p process.env.…` and `bash -c` both print it), so this is precedence, not plumbing. `--settings` is the form that works; any A/B between two proxy builds must read the target listener's log. Recorded as a trap in `CLAUDE.md` and a procedure in `docs/OPERATIONS.md`. This is what stalled issue #22.

## [0.6.2] — 2026-08-13

### Fixed
- **The statusline segment vanished from the bar for one frame, roughly once a minute.** The three quota gauges were fetched *serially on the render path*, so the render that found the 60 s cache expired took 1478–2216 ms — against cc-status's 2 s renderer kill, which reaps the whole process group. A killed renderer emits **zero** bytes (output is a single `stdout.write` at the end) and the composer drops empty segments, so the whole thing disappeared: measured 5 of 15 cold renders over the threshold. Because ~200 of every 201 renders hit a warm cache, it read as a rare flicker rather than a reproducible defect.
  Verified through the real cc-status composer (its discovery, its 2 s process-group kill), 10 cache-expiry cycles per version: **old 2/10 renders dropped the segment entirely and 4/10 exceeded 2 s; new 0/10 and 0/10**, cold render 1472–2160 ms → 221–253 ms. A 40-render run at Claude Code's real ~300 ms cadence across a naturally-aging cache: 0 drops, max 294 ms, one refresh.
- **One cache expiry cost ~5 rounds of API calls instead of 1.** The cache was written only *after* all three fetches returned, so every render launched during that ~2 s window saw a stale file and started its own round. Measured at the real endpoint latency, six renders 300 ms apart across ONE expiry issued five fetch rounds; now one. The render path no longer makes network calls at all — an expired value is served immediately (marked `!`) and refreshed by a **detached** background process, with a `refresh.lock` making it single-flight. `detached` is load-bearing rather than tidiness: the composer's group-kill reaps an ordinary child, so a non-detached refresher would die before writing and the gauge would go permanently blank — strictly worse than the flicker. Verified by probe (cache written: YES detached / NO non-detached) and locked by a test that reproduces the composer's exact kill sequence.
- **The two tools spelled the same reset time differently (backlog item 10).** `/cc-proxy:status` rendered an absolute UTC stamp while the statusline rendered a relative countdown, making a reader in any other zone do the arithmetic. `formatDuration()` now lives in `scripts/quota.js` and both call it; the CLI shows `(resets in 2h15m, <UTC>)`, keeping the absolute form because that report gets pasted into issues. Never a timezone bug — both were already timezone-independent.

### Added
- **Clock-drift detection on the quota gauges (backlog item 11).** Every reset countdown assumed the local clock agreed with the vendor's; when it doesn't, the gauge is wrong by exactly that offset and looks perfectly plausible. The reference clock was already free — both quota endpoints return a `Date` header on calls the fetchers make anyway — so past a deliberately loose 60 s threshold (request latency inflates apparent skew by up to the round-trip time) the statusline marks the gauge `?` and `/cc-proxy:status` names the offset and direction. Absent means "checked and fine", never `0`.

Not proxy configuration, so deliberately absent from `.env.example` and the README env table.

### Fixed
- **`claude-haiku-*` could be routed to a third party by a provider selector (invariant 4).** The haiku pin tested the **raw** model id, so `glm:claude-haiku-4-5-…` skipped the pin *and* arrived upstream as the bare haiku id — Claude Code's internal ops (titles, summaries) billed to a third-party backend. The pin now tests the **stripped tail** and discards any selector, so it outranks the lens. Found by adversarial review, not by the design; mutation-verified at both the unit and end-to-end layer (pinning on the raw id again fails 2 tests).
- **`docs/models.html` filed a model under the wrong provider and duplicated it.** The renderer threw away the published `provider` field and re-derived it through the cost-ranked router, so bare `deepseek-v4-pro` and its own `qwen:deepseek-v4-pro` alias landed side by side on the Qwen card while DeepSeek's card lost the model it owns. Display follows **namespace ownership**; routing follows **cost**; the renderer now reads `m.provider` (with the router kept only as a fallback for a proxy too old to publish it). `scripts/list-models.js` had the same defect and got the same fix.
- **`coerceCreated()` accepted any string as a date.** The field promises ISO-8601 but the string branch was passed through verbatim, so a vendor sending `"n/a"` would have put that on the wire. Unparseable strings now null; parseable ones pass through **verbatim** rather than round-tripping through `Date`, which would silently rewrite a vendor's offset (`+02:00` → `Z`) and drop sub-second precision on a value that is already valid. Latent, not live — every current backend sends ISO or a unix number. (Raised by Copilot on PR #18.)
- **`handleProxy()` mutated the inbound request body** when applying the selector strip. `stripAssistantThinking()` returns the caller's own object when it strips nothing, so `stripped.body.model = upstreamModel` edited the parsed inbound body in place. Nothing read it afterwards — `inboundModel` is captured first and the body is parsed fresh per request — so this was latent; it now builds an outbound object instead. (Raised by Copilot on PR #18.)
- **`coerceCreated()` discarded unix timestamps**, so **372 of 396** published entries shipped `created_at: null` — OpenRouter sends `created` as unix seconds for all ~400 of its models, making "sort by newest" impossible for any consumer. The original rule ("never emit a non-ISO value") is better served by converting than by dropping. Seconds vs milliseconds is decided by magnitude; junk still nulls rather than emitting `Invalid Date`. **8 → 391** dated entries.

### Changed
- **A catalog now lists what a backend SERVES, including foreign ids.** Previously a leg's static list held only its own vendor's models and a cross-vendor route was derived from `ROUTES` alone. That inverted once Qwen and OpenRouter became live legs: a catalog is then a mirror of another host's response, and its offline fallback must match it — so `DEFAULT_QWEN_MODELS` legitimately contains `glm-5.2` and `deepseek-v4-pro`. **Three axes, kept apart:** the catalog says what is *reachable* there, `ROUTES` says who serves it *cheapest*, and namespace ownership decides the *published spelling*. A foreign catalog id must have a `200` `ROUTES` entry naming that backend, or it claims a route nothing probed. The old locking test ("no static catalog restates a route it does not own") was replaced accordingly.
- **`OPENROUTER_MODELS` is now a pin, not a default.** Unset, the leg is fetched live with a curated fallback; setting it pins the list and skips the fetch.

### Docs
- README, `docs/ARCHITECTURE.md`, and `docs/OPERATIONS.md` described Qwen and OpenRouter as static curated lists — including the claim that Qwen exposes no `/models` endpoint — and stated that a multi-backend model "appears once under its cheapest route as the bare id", which ownership-based spelling made false. All corrected, and the `usable` wire field documented in all three per the `/v1/models` coupling.
- `docs/specs/route-selection.md` marked **SHIPPED**; its discovery section is flagged SUPERSEDED with what shipped instead and why.

## [0.4.0] — 2026-07-13

### Fixed
- **Plugin updates now actually reach the running proxy.** Two compounding pins kept users on stale proxies forever: `/cc-proxy:setup` wrote a **version-pinned** `PROXY_PATH` (`…/cache/betmoar/cc-proxy/<version>/bin/cc-proxy.js`) into settings.json, and the SessionStart hook's port probe treated *any* listener as "already up" — so after `claude plugin update`, the new cache dir sat unused while the old detached process kept serving.   3. **`POST /_shutdown`.** New loopback endpoint for that replacement: closes the listener, drains in-flight responses, severs idle keep-alive sockets, exits when the event loop empties. GET gets a `405` so a stray browser hit can't kill the proxy.

### Fixed
- **Inbound hop-by-hop headers are now stripped before forwarding.** `buildUpstreamHeaders` copied every inbound header (via `applyAuth`) and then set `content-length`, but never deleted `transfer-encoding`. The proxy always sends a fully-buffered body with an exact `content-length`, so forwarding an inbound `Transfer-Encoding: chunked` alongside it tripped upstream request-smuggling protections (RFC 9110 §7.6.1) — a bare `400` before the request reached any handler. Any client sending a chunked-body request failed with a misattributed upstream error (latent today: Claude Code sends `Content-Length`). All hop-by-hop headers (`connection`, `keep-alive`, `proxy-authenticate`, `proxy-authorization`, `te`, `trailer`, `transfer-encoding`, `upgrade`) are now dropped in `src/providers.js`. Locked by `test/providers.test.js` "drops inbound hop-by-hop headers" and `test/server.test.js` "chunked inbound body…" (buffered + streaming paths).
- **Statusline liveness probe honors `PROXY_PORT` from `~/.env`.** `scripts/statusline.js` evaluated its module-level `PROXY_PORT` const *before* the `loadEnv()` call lower in the file, so a port configured only in `~/.env` (a path `.env.example` documents) was silently ignored — the probe watched port 4000 while the proxy ran elsewhere, showing a false "proxy down" (or hiding a real one). `loadEnv()` now runs immediately after the imports, before any `process.env` read. Locked by `test/statusline.test.js` "liveness probe honors PROXY_PORT from ~/.env".

### Changed
- **Upstream error handling deduplicated across forward paths.** `onUpstreamError` and `parseMaybeJson` are now exported once from `src/proxy.js` and consumed by `src/server.js`, replacing two hand-copied blocks. The 502-before-headers / teardown-after-headers contract can no longer drift between the streaming and buffered paths — the same duplication class that shipped the query-string bug twice. Both 502 paths remain locked by the existing e2e timeout tests.
- **`docs/OPERATIONS.md` env table completed.** Added the four documented-elsewhere-but-missing knobs: `PROXY_HOST`, `PROXY_UPSTREAM_TIMEOUT_MS`, `DEFAULT_BACKEND`, `PROXY_LOG_MAX_BYTES`. Now enforced by a new coupling test asserting every `.env.example` key is documented in both `README.md` and `docs/OPERATIONS.md`.
- **Cross-file couplings are now test-locked** (`test/couplings.test.js`): the `PROXY_PORT` default (4000) is asserted identical across `src/config.js`, `hooks/proxy-lifecycle.js`, `scripts/status.js`, `scripts/statusline.js`; the `hooks.json` 10 s kill is asserted to exceed the lifecycle ready-poll default with headroom; and the env-doc coupling above. These were documented-only couplings that a future edit could silently break.

## [0.3.4] — 2026-07-09

### Fixed
- **`~/.env` is now the single source of truth for API keys, and the proxy loads it.** `bin/cc-proxy.js` loaded only the repo-root `.env` (never `~/.env`), so an install where `GLM_API_KEY` lived in `~/.env` exited 1 with `GLM_API_KEY is not set.` — the proxy refused to start. ## [0.3.1] — 2026-07-05

### Fixed
- **Query strings now reach the upstream.** Both forward paths dropped the `?query` portion of the inbound URL (`/v1/messages?beta=true` arrived upstream as `/v1/messages`), silently changing API behavior. Upstream request options are now built by a single shared `upstreamRequestOptions()` in `src/proxy.js`, so the streaming and buffered paths can no longer drift apart (the bug had shipped identically in both copies).
- **Client aborts propagate upstream.** Cancelling a turn (Esc, closing a session) mid-response previously left the upstream request running to completion — billing tokens into a dead connection. The proxy now destroys the upstream request when the client goes away before the response finishes, on both paths.
- **Inbound `x-api-key` no longer leaks to third-party backends.** When Claude Code authenticates with `ANTHROPIC_API_KEY` it sends `x-api-key`; the bearer (OpenRouter) path forwarded it upstream. Both non-OAuth auth strategies now drop it alongside `Authorization`.
- **Request-stream error guard.** A client that resets the connection mid-upload emits `error` on the request stream; it now has a handler, removing the one place an unhandled (process-fatal by contract) `error` event could reach the shared long-running proxy.
- **Statusline GLM quota fetch gained an 800 ms timeout** (matching the OpenRouter fetch) so a hanging quota endpoint fails fast into the stale-cache path instead of stalling every render.
- **`bin/cc-proxy.js` fails loud and clean**: an invalid `PROXY_PORT` and `EADDRINUSE` (two SessionStart hooks racing past the TCP probe) now print a one-line diagnostic instead of an uncaught stack trace in the log.
