# Changelog

All notable changes to cc-proxy are recorded here. Versions follow [semver](https://semver.org/); `package.json` is the single source of truth and propagates to `.claude-plugin/plugin.json` via `scripts/sync-version.mjs`.

## [0.6.1] — 2026-08-11

### Added
- **`/cc-proxy:bench` — the manual refresh for model facts.** Nothing runs automatically; both sub-commands are on request and write under `~/.claude/cc-proxy/`.
  - `bench grades` joins benchlm.ai (capability) with OpenRouter (price) into `grades.json`. **`grade` is read from the vendor's own version numbering, not from a benchmark score** — that part needs no eval (`glm-5.2 > glm-5.1` is a fact the id states), and using scores there actively inverts: benchlm marks NEW models `estimated` and mature ones `supported`, so score-ranking put `GLM-5.1` (66.9, supported) above `GLM-5.2` (63.03, estimated), while excluding estimates left the three most-used ids ungraded entirely. benchlm's score still ships as its own field with an `evidence` marker, for the cross-vendor question that genuinely needs measurement. Within one version, a variant rank orders `pro`/`max` above `flash`/`turbo` — otherwise an alphabetical tiebreak graded `deepseek-v4-flash` above `deepseek-v4-pro`. Anthropic gets an explicit product-line order, the one place a version number cannot help. Every spelling of one model (`deepseek-v4-pro`, `deepseek/deepseek-v4-pro`) shares a grade and occupies one rung. An id benchlm does not cover **omits** `score` rather than defaulting it — the same rule `context_window` already follows.
  - `bench speed` times one minimal turn per route and **appends** to `speed.jsonl`; `--report` gives median and p95 over the series. One ping is noise. It speaks HTTP straight to the proxy rather than driving the CLI (which cannot be retargeted per invocation — issue #25), and records `proxy_pid` + `proxy_version` with every row so a series spanning a binary swap is flagged rather than silently averaged (issue #24). It measures the ROUTE and never feeds `grade`. `claude-*` is skipped by default: the route is OAuth passthrough, so a script call has no credentials to forward and answers 401 regardless of route health.
- **Shared visual identity for the cc-* plugin family** — a rust/petrol palette applied to the generated model card, plus `docs/brand/generate-cc-plugin-family-draft.py`, the generator for the family's identity assets.
- **Documentation for the runtime state directory** (`docs/OPERATIONS.md`): what `~/.claude/cc-proxy/` holds, who writes each file, and that none of it is required — delete any of it and the proxy still starts and routes.

### Changed
- **BREAKING — `grade` is now OMITTED for a model nobody has assessed, and `Economy` is retired.** Two changes to what the published field MEANS, so `"grade" in entry` is now the only correct way to read it (never a null check, never an unconditional read).
  - **No default.** `DEFAULT_GRADE` is gone: an id absent from both `MODEL_GRADES` and the `bench grades` refresh carries no `grade` key at all — never `null`, never a placeholder — exactly as `context_window` already omits an unknown window. Measured 2026-08-07 against the live proxy, **299 of 320** usable entries shipped the `Specialist` default (7 Flagship, 9 Strong, 5 Economy), so the field asserted a verdict on 299 models nobody had looked at and a consumer could not tell those from the 21 real ones. Grading ~320 live-catalog ids by hand is not going to happen, so the field is scoped to what has actually been assessed instead.
  - **`Economy` removed; the allowed set is exactly `Flagship` / `Strong` / `Specialist`** (exported as `GRADES`). It named a COST class on a CAPABILITY axis, which is the one conflation the tier/grade split exists to prevent — `deepseek-v4-flash` measured equal to `glm-5.2` on implementation work. It was already de-facto gone: `bench grades` has only ever emitted the other three. The five ids that carried it (`glm-4.7`, `glm-4.6`, `glm-4.5`, `glm-4.5-air`, `qwen3.6-flash`) are now `Specialist` — NARROW, the residual *assessed* bucket, which "unknown" is no longer allowed to borrow.
  Affordable now precisely because `grade` has no consumer yet: cc-operator reads `/v1/models` for membership only. `docs/models.html` renders an unassessed row as **ungraded** (0 of 4 dots, sorted last) — a display word for the absence, never a wire value.
- **`GLM_API_KEY` is optional; the proxy no longer exits when a backend key is missing (issue #20).** GLM was the original single backend and registered unconditionally, while OpenRouter, DeepSeek and Qwen were each gated on their key — and `bin/cc-proxy.js` exited `1` when the glm entry existed without one. A user with only a DeepSeek key, or no third-party key at all, could not start the proxy, even though Claude is OAuth and would have served the whole session. `buildProviders()` now gates glm like the rest, so a `glm-*` id with no key falls through to the default backend instead of resolving to a dead entry that 401s upstream. The exit is **replaced, not relocated**: gating the provider makes `glm` `undefined`, which would have made `if (glm && !glm.apiKey)` silently stop firing, so in its place is a startup notice naming the active backends — with a distinct line when GLM specifically is absent, because an unset `GLM_API_KEY` is more often a typo than a choice. Port validation still exits; that one is a real misconfiguration. `/cc-proxy:setup` now offers the GLM key and continues if you skip it.

### Fixed
- **`docs/models.html` published the developer's own grades, not the repo's.** The renderer grades in-process through `gradeOf()`, which overlays `~/.claude/cc-proxy/grades.json` on the built-in `MODEL_GRADES` — so `pnpm models:html` shipped whatever the person regenerating had last benched. The committed artifact carried `glm-5`/`claude-sonnet-5`/`qwen3.8-max` as `Specialist`/`Specialist`/`Flagship` against the repo's `Strong`/`Strong`/`Strong`, and `claude-fable-5` as `Strong` against `Flagship`. The test suite learned this in 9ac2bf2 ("isolate HOME so the suite stops reading the developer's grades.json"); the release procedure never did. `models:html` now runs through `scripts/render-html.mjs`, which uses a temp HOME holding only a symlink to `~/.env`. Isolating the whole HOME is the obvious fix and is WRONG — `loadEnv()` reads `~/.env` from it, so every key vanishes, no live leg registers, and the page collapses to the Claude card alone (measured: 40 rows → 3, which is how this was caught). The wrapper refuses to write a page under 10 rows for that reason.
- **Every OpenRouter row rendered a blank context window.** `/v1/models` publishes a real `context_window` for those ids (from OpenRouter's own `context_length`), but the renderer threw the field away and re-derived from the curated `CONTEXT_WINDOW` table, which only covers the ids this repo curates — so all 20 OpenRouter rows showed nothing while the API had the number in hand. `windowFor()` now prefers the published integer and falls back to the table; `groupByProvider()` carries the field through its row rebuild, which is where the first attempt at this fix silently lost it. Same "re-derivation beats the published field" class as the provider mix-up the file already warns about, and as the lensed-row window below.
- **A `<provider>:`-lensed row rendered a blank context window.** `CONTEXT_WINDOW` is keyed by the BARE vendor id, but `docs/models.html` only ever sees the published id, which may carry a lens. `tierFor()` already aliased through the tail for exactly this reason; the window lookup on the next line of the same `.map()` did not — so `qwen:glm-5.2` showed no window beside `glm-5.2` showing `1M`, the same model answering two ways. Three such rows shipped. `windowFor()` now applies the same fallback, keeping `Object.hasOwn` on both reads (ids come from live catalogs, so `constructor` would otherwise inherit a function). Found by an external review after five internal lenses aimed at `grade` walked past the lookup beside it.
- **`/cc-proxy:bench <sub> <args>` glob-expanded its arguments.** `set -- $ARGUMENTS` splits deliberately — that is how the sub-command is parsed at all, since a slash command has no positional parameters — but unquoted expansion also expands pathnames: measured in a directory holding two files, `bench speed *` split into three words (`speed aaa.txt bbb.txt`) instead of two, and that argv goes straight to a script. `set -f` around the split keeps the word-splitting and drops the globbing; verified across all five argv shapes, including empty and unknown sub-commands.
- **A killed `bench grades` could leave truncated JSON that the proxy then silently ignored.** The refresh wrote `grades.json` with a single `writeFileSync`, so a process killed mid-write (SIGKILL, OOM, full disk) left a partial file; the next proxy start failed `JSON.parse`, caught it, and fell back to the built-in table with nothing said. That contradicts the command's own promise — "a stale file is useful, a silently-empty one is a lie" — which covers the script throwing before it writes, but not a kill during the write. `writeGradesFile()` now writes `<path>.tmp-<pid>` and renames over the target, so a reader sees the old file or the new one, never a half of either. `bench speed` keeps its plain append on purpose: JSONL, where a torn write costs one line and no reader parses the whole file.
- **A non-regular file at `grades.json` hung proxy startup forever.** `loadRefreshedGrades()` runs at module import and its `try/catch` stops a throw but not a block: with a FIFO at that path, `node bin/cc-proxy.js` never finished booting (`timeout 6` → exit 124, nothing listening), and through the SessionStart hook that is `ECONNREFUSED` for every session in the project. The path is now `statSync`-ed and read only when it is a regular file. Contrived as an input, load-bearing as a property — a config read on the boot path must not be able to hang the boot.
- **Three lookups in `scripts/list-models.js` inherited from `Object.prototype`.** `DISPLAY[pid]`, `CONTEXT_WINDOW[bare]` and `DEEPSEEK_PRICING[bare]` were bare bracket reads on keys that come from LIVE vendor catalogs, so an id named `constructor` returned `[Function: Object]` — the same class already fixed in `src/models.js` and `render-models.js`, left standing in the dev CLI. All three now use `Object.hasOwn`, and the row builder moved out of `main()` into an exported `buildRow()` so a test can reach it at all.
- **A hand-edited `grades.json` could publish any string as a `grade`.** The refresh loader accepted any non-empty value, and a live proxy was made to serve `"grade":"SuperDuperMax"` and `"grade":"   "` on `/v1/models` — straight into the field another plugin dispatches on, from a file that is user-writable and written by an interruptible command. Grades are now checked for membership in `GRADES`; a bad value skips that ENTRY (the id falls back to its built-in grade) rather than voiding the whole refresh, matching how a malformed entry was already handled. This is also what stops a `grades.json` written before this release from smuggling the retired `Economy` back onto the wire.
- **`docs/models.html` and `/v1/models` disagreed about a model after `bench grades`.** `scripts/render-models.js` did `MODEL_TIERS = MODEL_GRADES` and looked the grade up in that table, i.e. read the BUILT-IN map while the endpoint read `gradeOf()` — table overlaid with the refresh. Re-exporting a table is not sharing a lookup, so the line written to make drift impossible was the line causing it, in a file whose own docstring forbids "the same curated data in two places". The renderer now calls `gradeOf()`, keeping only its `<provider>:` alias fallback (`gradeOf()` deliberately has none — discovery grades the bare id before the lens is applied).
- **Bare `deepseek-v4-pro` routed to the Qwen Token Plan instead of native DeepSeek when both were configured (issue #19).** The "plan before credits" policy (0.5.1) made the bare id — the one `/model` sets — spend prepaid Qwen capacity before metered DeepSeek credits. But the plan's gateway injects a **+79-token preamble**, so the two routes are behaviourally non-interchangeable, and a user who tuned a prompt against native weights was silently rerouted. The bare id now resolves **native when native DeepSeek is registered**. `rankRoutes()` (`src/routes.js`) was strengthened: the NATIVE provider now sorts ABOVE tier (previously it only broke tier ties), so native DeepSeek (tier 3) wins over the Qwen plan (tier 2) for this id. The plan route stays in the table: a plan-holder **without** a native DeepSeek key still lands on it (native not registered → next-ranked route), and the `qwen:` selector always reaches it. `glm-5.2` is unaffected (it already resolved native via the tiebreak). This reverses a deliberate, documented policy (CLAUDE.md backlog item 8); the probe matrix, tier vocabulary, and cost rank there remain the reference. (A first attempt used a `default: false` route flag to exclude the plan outright; review caught that it stranded plan-only users, so it was replaced by the registration-aware native-first sort.) **On billing:** setting `DEEPSEEK_API_KEY` now means bare `deepseek-v4-pro` spends that key's prepaid DeepSeek balance rather than Qwen plan capacity — which is what adding a credit key asks for, so this is intended, not a surprise. The case worth checking is the other one, and it holds: **without** a DeepSeek key the bare id still falls back to the plan's resold copy (verified across plan-only, plan+GLM and plan+OpenRouter — all resolve to `qwen`), so a plan-holder never loses the model. `qwen:deepseek-v4-pro` reaches the plan explicitly either way.
- **The version handshake evicted a proxy NEWER than the plugin tree (issue #24).** `ensureProxyRunning()` compared versions with `!==`, so *any* difference read as stale — including a dev tree deliberately ahead of the installed plugin. Because SessionStart fires on every `claude` invocation, the client under test kept replacing the binary under test: a working tree running `bin/cc-proxy.js` at the next version could never hold port 4000 against an older cached build, and a routing fix was read as broken four times in a row before the cause was found. The comparison is now ordered (new `isOlderVersion()`, numeric per segment — a string compare would rank `0.6.10` below `0.6.9`), so only a genuinely older proxy is replaced. The staleness protection is unchanged in the direction it was written for: an old long-lived proxy is still swapped out after a plugin update, and a `null` version (too old to report one) still counts as behind.
- **`docs/models.html` regenerated against a 0.6.1 proxy.** The committed artifact predated the routing and catalog work in this release, so it under-reported the model count (320 -> 322) and was missing the "also on plan" tag on `deepseek-v4-pro`. The artifact is generated against a LIVE proxy and CI cannot rebuild it, so a stale copy ships green and silent — the release procedure in `CLAUDE.md` now names the regeneration step, including the PID check (`/_status` reports what ANSWERED, not what is bound).
- **The Qwen card under-reported the plan's scope.** `QWEN_PLAN_ALSO` (`scripts/render-models.js`) omitted `deepseek-v4-pro` on the theory that a natively-routed id is not a "dup" — backwards: native routing is the PRECONDITION for the "also on plan" tag, which is exactly why `glm-5.2` carries it. Caught in review on #21; `deepseek-v4-flash-0731` correctly stays out, being plan-ONLY with no native route to cross-reference. **Now locked by `test/couplings.test.js`** — the two sets are hand-written copies of one curated fact in files that never import each other, so the next drift was silent again: routing keeps working and the page just tells the reader less than the truth. The lock asserts containment, not equality, because only one direction is an error — `glm-5.2` is legitimately in the display set and not the predicate (the glm predicate claims it first, so adding it there would be dead code). Mutation-verified in both directions: dropping `deepseek-v4-pro` from the display set reproduces the #21 drift and fails; adding an id to the router set alone fails too.
- **`/cc-proxy:bench grades` refreshed a file nothing read.** The command wrote `~/.claude/cc-proxy/grades.json`, but `gradeOf()` returned the built-in `MODEL_GRADES` regardless — so `GET /v1/models` published one set of grades while the command showed the operator another, and they had already diverged on **13 of 24 ids** (`qwen3.8-max` Strong vs Flagship, `glm-4.7` Economy vs Specialist, `claude-sonnet-5` Strong vs Specialist). cc-operator dispatches on the published field, so it was dispatching on the stale half — the "same curated data in two places" drift `test/couplings.test.js` exists to catch, inside one repo, with no test covering it. `gradeOf()` now reads the refreshed file at STARTUP and falls back to the built-in table per id. That is config, not state, and invariant 2 holds: the file is written by a manual command and read once at boot, never on a request path, so a running proxy's answers still never change for its lifetime — the `~/.env` posture. Missing, truncated, or hand-corrupted files fall back silently (discovery must keep answering), a single malformed entry is skipped rather than voiding the file, and an id named `constructor` cannot inherit from `Object.prototype`. Locked by `test/grades-refresh.test.js`, mutation-verified.
- **`/cc-proxy:bench speed --report` did not run the report.** A slash-command body has no positional parameters — Claude Code substitutes the argument tokens textually before any shell runs, and substitutes only `$ARGUMENTS` and `$1`. Two distinct defects came out of that, both caught by running the real command rather than testing the template: first `shift; "$@"` forwarded nothing (`$@` expands against an empty argv), silently dropping `--report` and turning a read-only summary into a full billed measurement run against every configured backend; then a rebuild from `$2`/`$3` failed differently and worse — those survive as literal text and expand to nothing, while `$1` was set to `--report` (the LAST token, not the first), so `case "$1"` matched no branch and fell through to the `grades` default, running the wrong sub-command entirely. Now `set -- $ARGUMENTS` word-splits the whole argument string into a real argv, with an explicit error on an unknown sub-command instead of a silent fallthrough. Verified against the live harness across five invocation shapes in both zsh and bash.
- **`/cc-proxy:bench grades` published grades that contradicted the table it refreshes.** Two normalization gaps in `gradeByVendorPosition()`: a `<provider>:` lens took a rung of its own (`qwen:deepseek-v4-pro` sat between the bare id and `deepseek-v4-flash`, pushing the real second model from Strong down to Specialist), and a dated build ranked as a separate model (`deepseek-v4-flash-0731` graded Specialist while `MODEL_GRADES` grades it Strong, "as its bare sibling ... which it is a dated snapshot of"). `normalizeName()` now strips the lens and folds a dated `deepseek-*` build onto its bare form — scoped to `deepseek-` exactly as `providers.js` `DATED_ID` is, because this key also indexes the benchlm score and OpenRouter price maps and an unscoped `-\d{4}$` would fold `claude-sonnet-4-5-20250929` onto its base and hand it another model's price.
- **`scripts/render-models.js` inherited from `Object.prototype` on two live-catalog lookups.** `tierFor()` and the `context_window` lookup used bare indexing, so a vendor id of `constructor`/`toString` returned a function — and `??` cannot guard that (a function is neither null nor undefined), so the row would render the raw function text as its tier. Both now use `Object.hasOwn`, the same guard `src/routes.js` `tierOf()` and `src/models.js` `withContextWindow()` already carry; the renderer had been missed.
- **`PROVIDER_IDS` had no coupling lock.** The set `parseModelSelector()` strips a `<provider>:` lens for is hand-maintained and deliberately not derived from the registry (the strip must work when a backend holds no key — issue #20), but nothing caught a provider added to `buildProviders()` and not to the set: the backend would route fine by predicate while `<new>:<model>` forwarded the raw lens upstream as a model id. Now locked by `test/couplings.test.js` (mutation-verified) and documented as step 1b in `CONTRIBUTING.md` plus a couplings entry in `CLAUDE.md`.

## [0.6.0] — 2026-08-07

### Added
- **Provider-namespaced model ids: `<provider>:<model>`.** The bare id routes to the **cheapest** backend serving it; every other route stays reachable by prefixing the backend — `deepseek:deepseek-v4-pro` reaches DeepSeek's own endpoint, `qwen:glm-5.2` the plan's copy. This closes a gap 0.5.1 opened: "plan before credits" moved bare `deepseek-v4-pro` to the Qwen Token Plan, whose gateway injects a preamble (**+79 input tokens**, measured on the same 9-word body), and no spelling was left that reached native DeepSeek. The selector is cc-proxy's LOCAL lens — no backend has heard of it — so it is stripped before forwarding and the backend only ever sees its own id. **Colon only.** `/` was left to OpenRouter untouched: probing showed the bare id already routes cheapest and the slash form already routes to the reseller (`qwen3.7-max` → plan, `qwen/qwen3.7-max` → OpenRouter), so a slash selector buys nothing in either direction — and rewriting OpenRouter's `includes("/")` predicate into an allowlist would have been the price. `:` was live-verified through Claude Code's `/model` picker on 2026-08-06.
- **A probed route table (`src/routes.js`).** `ROUTES` records which (id, backend) pairs actually answer, with a cost tier per route: **1** OAuth/Anthropic, **2** prepaid plan, **3** metered credits, **4** reseller. `rankRoutes()` orders them and `tierOf()` publishes the winner's tier. Every cell was probed against the live host rather than read from a vendor page — both QwenCloud's public model list and the account's own plan page omit ids the gateway genuinely serves (`glm-5.2`, `deepseek-v4-flash-0731`). Re-probe before each release; the table rots.
- **Live catalogs for Qwen and OpenRouter** (27 → ~396 discovered models). Qwen's catalog is on the OpenAI-compatible path `/compatible-mode/v1/models`; the Anthropic skin the proxy forwards to answers `404 "Not support"`, which is why this leg looked catalog-less for so long and was hand-curated. Each live leg keeps its curated list as an offline fallback, so a flaky network degrades to the previous behavior instead of an empty leg. `anthropic/*` ids are dropped from OpenRouter rather than flagged: reaching Claude through a reseller means paying per token for what the session's OAuth plan already covers.
- **`provider`, `tier`, and `grade` on every `GET /v1/models` entry.** `tier` is what the **route costs** (1–4, from `src/routes.js`); `grade` is what the **model can do** (`Flagship`/`Strong`/`Specialist`/`Economy`, from `MODEL_GRADES`). They cross-cut and must never be derived from each other — a resold Flagship is tier 4 *and* Flagship; a cheap fast model is tier 2 *and* Economy. `MODEL_TIERS` moved from `scripts/render-models.js` into `src/models.js` as `MODEL_GRADES`, with the renderer re-exporting it so the two cannot drift. **This makes a curated opinion API surface: a new model with no grade silently ships `Specialist`** (see backlog item 9 — the grades still want evals).
- **`usable: false`** on discovery entries a backend serves but this proxy cannot use — multimodal ids wanting a different request schema, `:batch` variants, `~latest` aliases. Published rather than dropped so a consumer can grey them out instead of wondering where they went; the field is **absent** when the entry is usable, so test `entry.usable !== false`.
- **`MODELS_HTML_LIMIT`** caps `docs/models.html` at 20 rows per provider card (`0` renders everything). OpenRouter alone serves ~300 usable models, which buried the four small interesting cards under thousands of lines of scroll. Rows sort by **grade, then newest within a grade**, so a fresh Economy model cannot push a Flagship off a capped card. A capped card states both numbers and prints how many it hid. Not proxy configuration, so deliberately absent from `.env.example` and the README env table.

### Fixed
- **`claude-haiku-*` could be routed to a third party by a provider selector (invariant 4).** The haiku pin tested the **raw** model id, so `glm:claude-haiku-4-5-…` skipped the pin *and* arrived upstream as the bare haiku id — Claude Code's internal ops (titles, summaries) billed to a third-party backend. The pin now tests the **stripped tail** and discards any selector, so it outranks the lens. Found by adversarial review, not by the design; mutation-verified at both the unit and end-to-end layer (pinning on the raw id again fails 2 tests).
- **`docs/models.html` filed a model under the wrong provider and duplicated it.** The renderer threw away the published `provider` field and re-derived it through the cost-ranked router, so bare `deepseek-v4-pro` and its own `qwen:deepseek-v4-pro` alias landed side by side on the Qwen card while DeepSeek's card lost the model it owns. Display follows **namespace ownership**; routing follows **cost**; the renderer now reads `m.provider` (with the router kept only as a fallback for a proxy too old to publish it). `scripts/list-models.js` had the same defect and got the same fix.
- **`coerceCreated()` accepted any string as a date.** The field promises ISO-8601 but the string branch was passed through verbatim, so a vendor sending `"n/a"` would have put that on the wire. Unparseable strings now null; parseable ones pass through **verbatim** rather than round-tripping through `Date`, which would silently rewrite a vendor's offset (`+02:00` → `Z`) and drop sub-second precision on a value that is already valid. Latent, not live — every current backend sends ISO or a unix number. (Raised by Copilot on PR #18.)
- **`handleProxy()` mutated the inbound request body** when applying the selector strip. `stripAssistantThinking()` returns the caller's own object when it strips nothing, so `stripped.body.model = upstreamModel` edited the parsed inbound body in place. Nothing read it afterwards — `inboundModel` is captured first and the body is parsed fresh per request — so this was latent; it now builds an outbound object instead. (Raised by Copilot on PR #18.)
- **`coerceCreated()` discarded unix timestamps**, so **372 of 396** published entries shipped `created_at: null` — OpenRouter sends `created` as unix seconds for all ~400 of its models, making "sort by newest" impossible for any consumer. The original rule ("never emit a non-ISO value") is better served by converting than by dropping. Seconds vs milliseconds is decided by magnitude; junk still nulls rather than emitting `Invalid Date`. **8 → 391** dated entries.

### Changed
- **A catalog now lists what a backend SERVES, including foreign ids.** Previously a leg's static list held only its own vendor's models and a cross-vendor route was derived from `ROUTES` alone. That inverted once Qwen and OpenRouter became live legs: a catalog is then a mirror of another host's response, and its offline fallback must match it — so `DEFAULT_QWEN_MODELS` legitimately contains `glm-5.2` and `deepseek-v4-pro`. **Three axes, kept apart:** the catalog says what is *reachable* there, `ROUTES` says who serves it *cheapest*, and namespace ownership decides the *published spelling*. A foreign catalog id must have a `200` `ROUTES` entry naming that backend, or it claims a route nothing probed. The old locking test ("no static catalog restates a route it does not own") was replaced accordingly.
- **`OPENROUTER_MODELS` is now a pin, not a default.** Unset, the leg is fetched live with a curated fallback; setting it pins the list and skips the fetch.

### Docs
- README, `docs/ARCHITECTURE.md`, and `docs/OPERATIONS.md` described Qwen and OpenRouter as static curated lists — including the claim that Qwen exposes no `/models` endpoint — and stated that a multi-backend model "appears once under its cheapest route as the bare id", which ownership-based spelling made false. All corrected, and the `usable` wire field documented in all three per the `/v1/models` coupling.
- `docs/specs/route-selection.md` marked **SHIPPED**; its discovery section is flagged SUPERSEDED with what shipped instead and why.

## [0.5.1] — 2026-08-04

### Added
- **`docs/models.html` now shows how each backend is reached, not just what it serves.** Every provider card carries two chips: **source** (`native` / `plan` / `reseller` — distance from the weights) and **billing** (`plan` / `credits`). They are deliberately independent, and the page is worth reading because they disagree: DeepSeek is `native`+`credits`, so its own endpoint is the *expensive* way to reach `deepseek-v4-pro`, while the Qwen plan route is prepaid. Neither is a capability claim (that is `MODEL_TIERS`, unchanged). The card for the fallback backend is marked `default`, and models the Qwen plan also serves but which still route natively (`glm-5.2`, `deepseek-v4-pro`) carry an `also on plan` tag — without it the plan's scope read as 6 models when the entitlement is 8. Locked by `test/render-models.test.js`, including an assertion that the two axes have not been collapsed into one.
- **`context_window` on `GET /v1/models` entries.** Every discovery entry for a curated id (GLM, DeepSeek native, Qwen) now carries `context_window` as an integer token count (e.g. `128000`, `1000000`) on the wire. ids with no curated window — the OpenRouter-prefixed ids (`deepseek/*`, `qwen/*`, `moonshotai/*`, `tencent/*`) and the `claude-*` ids — OMIT the field entirely; it is never emitted as `null`, so a consumer distinguishes "unknown" from "known" with `"context_window" in entry`. This is a **reversal** of the 0.4.3-era decision (recorded in `scripts/list-models.js`'s header) that context-window data was deliberately the display layer's concern, not the proxy's. Reason: a second consumer (the `cc-reload` Claude Code plugin, which budgets a session's context usage against its model's window) now needs the number programmatically, and hard-coding a duplicate model-id table in every consumer is exactly the drift failure mode this repo's own `test/couplings.test.js` exists to catch — so the curated table was promoted from the display script into `src/models.js` as the single source, and `scripts/list-models.js` now only formats it for humans (`128000` → `"128K"`). Rendered `/cc-proxy:models` output is unchanged (byte-identical) for every currently-covered id.

### Fixed
- **`deepseek-v4-flash-0731` routed to a backend that does not serve it.** The Qwen Token Plan serves DeepSeek builds under its own dated spelling, and that id exists *only* there — DeepSeek's native endpoint answers `400 The supported API model names are deepseek-v4-pro or deepseek-v4-flash`. - **Content-encoding blind spot on the buffered path.** The non-streaming path `JSON.parse`s the upstream response body to convert a GLM 200-overflow into a 400 and to inject `Retry-After` on a 1302 429; both silently degraded to plain passthrough if a backend ever gzipped those bodies (the parse just fails). `forwardBuffered()` now pins `accept-encoding: identity` upstream — a deliberate invariant-1 header exception, like the existing hop-by-hop drop, and it overrides whatever the client asked for. Locked by three `test/server.test.js` cases (buffered forces identity, inbound `gzip` does not survive on the buffered path, streaming path unchanged).
- **Prototype-inherited model ids leaked a garbage `context_window`.** `withContextWindow()` looked the id up with `CONTEXT_WINDOW[entry.id]` on an object literal, so ids that name an `Object.prototype` member resolved to the inherited value instead of missing: a vendor id of `__proto__` shipped `"context_window": {}` on the wire, and `constructor`/`toString` attached a *function* (dropped by `JSON.stringify`, but present in the object `collectModels()` returns in-process). Now uses `Object.hasOwn`; locked by `test/models.test.js` "withContextWindow omits for prototype-inherited ids".
- **`checkPort()` (`hooks/proxy-lifecycle.js`) had no socket timeout.** The lifecycle TCP probe is polled by `waitReady`/`waitGone` inside the SessionStart hook, which hooks.json kills at 10s; a connect that is DROPped rather than REJECTed (loopback behind a deny-by-drop firewall) never fires `error`, so the first poll sat until the OS connect timeout (~75s) and the hook died with no proxy and no message. Now bounded at 300ms, mirroring `probePort` in `scripts/statusline.js`, with the timer cleared on both the connect and error paths so no live handle keeps the hook's event loop alive. Locked by two `test/proxy-lifecycle.test.js` cases (bounded resolve against an unrouted RFC 5737 address, and no timer leak on either terminal path).

### Fixed
- **`/cc-proxy:status` plugin-root resolution, rebuilt for the two shells it actually runs in.** The command resolved its plugin root from `$CLAUDE_PLUGIN_ROOT`, but that var is injected only in **hook** context — not into a slash-command's Bash — and the `PROXY_PATH` fallback stopped being written to settings.json in 0.4.0, so with both unset the command printed `cc-proxy: cannot locate plugin root` even with the proxy healthy. ## [0.4.0] — 2026-07-13

### Fixed
- **Plugin updates now actually reach the running proxy.** Two compounding pins kept users on stale proxies forever: `/cc-proxy:setup` wrote a **version-pinned** `PROXY_PATH` (`…/cache/betmoar/cc-proxy/<version>/bin/cc-proxy.js`) into settings.json, and the SessionStart hook's port probe treated *any* listener as "already up" — so after `claude plugin update`, the new cache dir sat unused while the old detached process kept serving. Fix, in three parts:
  1. **Self-resolved binary.** `resolveProxyPath()` (`hooks/proxy-lifecycle.js`) spawns `bin/cc-proxy.js` from the hook's **own plugin tree** — by construction the installed version.   3. **`POST /_shutdown`.** New loopback endpoint for that replacement: closes the listener, drains in-flight responses, severs idle keep-alive sockets, exits when the event loop empties. GET gets a `405` so a stray browser hit can't kill the proxy.

Both the GLM-quota and OpenRouter-credits fetchers in `scripts/statusline.js` now share one `QUOTA_FETCH_TIMEOUT_MS` constant (was two inline `800`s that dropped both providers into stale cache on slow networks); `scripts/status.js` moved `1500 → 2000` to match, so every provider on both surfaces times out identically.

## [0.3.1] — 2026-07-05

### Fixed
- **Query strings now reach the upstream.** Both forward paths dropped the `?query` portion of the inbound URL (`/v1/messages?beta=true` arrived upstream as `/v1/messages`), silently changing API behavior. Upstream request options are now built by a single shared `upstreamRequestOptions()` in `src/proxy.js`, so the streaming and buffered paths can no longer drift apart (the bug had shipped identically in both copies).
- **Client aborts propagate upstream.** Cancelling a turn (Esc, closing a session) mid-response previously left the upstream request running to completion — billing tokens into a dead connection. The proxy now destroys the upstream request when the client goes away before the response finishes, on both paths.
- **Inbound `x-api-key` no longer leaks to third-party backends.** When Claude Code authenticates with `ANTHROPIC_API_KEY` it sends `x-api-key`; the bearer (OpenRouter) path forwarded it upstream. Both non-OAuth auth strategies now drop it alongside `Authorization`.
- **Request-stream error guard.** A client that resets the connection mid-upload emits `error` on the request stream; it now has a handler, removing the one place an unhandled (process-fatal by contract) `error` event could reach the shared long-running proxy.
- **Statusline GLM quota fetch gained an 800 ms timeout** (matching the OpenRouter fetch) so a hanging quota endpoint fails fast into the stale-cache path instead of stalling every render.
- **`bin/cc-proxy.js` fails loud and clean**: an invalid `PROXY_PORT` and `EADDRINUSE` (two SessionStart hooks racing past the TCP probe) now print a one-line diagnostic instead of an uncaught stack trace in the log.
